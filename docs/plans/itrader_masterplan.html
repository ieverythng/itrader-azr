iTrader Masterplan

Last updated: 2026-09-24 Status: dataset v2, crossed RTH controls, and strict synchronous-PBT provenance are validated; the next matched P0 is paused launch-ready, and no v2 R0 candidate passes the Phase A economic gate Branch snapshot: agent/Watson-dev plus the uncommitted dataset-v2 implementation/evidence round

North star

iTrader is a governed proposer/curriculum plus numerical solver system. Keep learning, framing, deterministic gating, and execution separate.

offline: historical OHLCV -> proposer/curriculum -> validated TaskSpec pool
-> ITraderEnv -> numerical PPO solver -> held-out capability evidence
online: market window -> MarketFramer -> CandidateTask + WAIT -> solver score
-> DecisionGate -> RiskEngine -> Executor -> DecisionRecord

This is AZR-inspired adaptive curriculum learning, not literal zero-data AZR: historical OHLCV is external data, the proposer and numerical PPO solver are intentionally separate, and train_AZR.py is currently a bootstrap handoff.

Phase A — implemented solver baseline under performance revalidation

Status: measurement and PBT seams repaired; optimizer health is provisional and trading performance is not validated.

  • train_solo_V2.py selects SolverMLPFiLM.
  • ITraderEnv emits chronological price_window_flat + task_embedding.
  • TaskSpec is canonical; RewardEngine owns finite reward computation.
  • pnl_linear remains the historical/default optimization reward. It is learnable in the limited sense that PPO produced finite training signals and restorable policies; it is not yet proven to rank economic performance. Sharpe variants remain challengers and are not a recurrence prerequisite.
  • net_return is now an explicit challenger objective: gross arithmetic return minus configured turnover and terminal-liquidation costs, multiplied by one constant PPO scale. At the default 1 bp its episode sum divided by the scale exactly matches EpisodeEvidence.net_return; it does not alter broker or live execution semantics. PPO discounting with gamma < 1 remains an explicit difference from the undiscounted episode sum.
  • Family 00 is the only enabled learned family. 01/02 are bootstrap contracts; 03 is trade management; 04 is abstention/WAIT semantics.

Dataset-v2 baseline reset

Dataset v1 is now characterized rather than assumed. In an authenticated Alpaca SIP overlap, over 99.7% of audited closes matched after timestamp correction, but every v1 OHLC row was flat, volumes commonly appeared as exact multiples, and naive local timestamps shifted summer data by one hour. Old close-to-close PnL was therefore based on a genuine close path, not synthetic prices, while the input representation, volume, provenance, and earlier evidence seams were not sufficient for an economic promotion claim.

The immutable v2 snapshot contains 10,370,064 unique one-minute Alpaca SIP bars for AAPL, MSFT, AMZN, NVDA, AMD, AVGO, GOOGL, META, SPY, QQQ, IWM, and TLT from 2022-01-03 through 2026-09-22. It is split-adjusted, not dividend-adjusted, and partitioned by session/symbol/year. Phase A selects 5,515,061 RTH rows; extended hours are retained for Phase B. The snapshot hash is fac41f6d42f8c5b1eac739755667bb38407461f82c168d7955de26bb2e5fb79c.

The original fixed 32-episode v2 panel scores long-only at +0.05970% net and +0.00757 Sharpe/sqrt(bar), flat at zero, and short-only at -0.09970% net. A fresh 12-update no-cost R0 bridge remained active but ended at -0.80750% net. Its matched 1 bp optimization arm cut terminal turnover from 80.69 to 18.06, but did so by moving to 95.23% short and still lost -0.29511% net. This validates reward responsiveness, not economic edge. See the dated dataset-v2 R0 audit.

That original panel is retained for bridge comparability, not current selection: each horizon used different starts while semantic_v2 exposes horizon. The canonical P0 panel instead crosses eight explicit RTH starts with all four horizons. Its 1 bp controls are flat 0.00000% net/0 Sharpe, long-only -0.09785%/ +0.00827, short-only +0.05785%/-0.01558, random -1.31143%/-0.25857, and a seeded untrained FiLM policy exactly equal to short-only. This removes the horizon/start identity shortcut but remains a selection-informed development panel, so P1 still requires new chronological blocks.

The 2026-09-12 performance-validity audit restored both historical iteration-200 PBT checkpoints and replayed each on 288 symbol-safe diagnostic episodes. The final-score target averaged +0.0163% gross but -0.0728% net at 1 bp per turnover unit; the peak-score target averaged -0.0112% gross and -0.0950% net. Both were overwhelmingly flat. These are in-sample diagnostics because the historical run used the full Parquet file, but they disprove the interpretation that the shaped PBT score was itself profitable return.

The different historical gammas confirm that the long PBT run did mutate configurations after checkpoints became available. Ray's default numeric perturbation multiplied categorical gamma values by 0.8/1.2 without domain validation: one target ended at gamma=0.6272, while the other ended at the invalid gamma=1.188.

Mandatory Phase A revalidation gate

The engineering portion of this gate is now implemented and smoke-validated on the official random/generated ablation path. EpisodeEvidence, symbol-safe purged partitions, semantic_v2 task encoding, held-out net-return selection, bounded/diverse PBT, aligned checkpoints, equal exposure, restore-aware lineage, atomic stable provenance, all-member summaries, and the flat-schema capability report are present. The bounded two-member run ended at exactly 12 unique iterations and 13,520 timesteps per member and recorded real exploit/restore events. This establishes seam correctness, not trading performance.

Phase B — offline + replay/shadow work

Status: active scope; implementation and ordering remain under review.

Phase B includes both offline/curriculum work and online replay/shadow validation. It is not limited to proposer integration, and replay/shadow is not deferred until Phase C. Live broker execution remains outside this Phase B scope.

The solver/trunk/head structure is still an open design question. A shared recurrent trunk with family-specific policy/value heads is a proposal for the ongoing grill-me review, not an accepted architecture. Families 00–04 remain the roadmap; 00–02 may share Discrete(3) output width without settling input schemas, task semantics, reward assignments, or state ownership.

Solver standard (proposed, not settled)

Keep R0 as the control. Do not describe model registration as model selection. R1–R3 are unimplemented, and R4 is versioned as R4-v1. The shared-trunk and family-head arrangement remains open pending user review.

Historical provenance is authoritative:

Cell Identity Status
R0 MLP + implemented FiLM (tanh(gamma)*hidden + beta) Implemented/default
R1 Reset-every-step window LSTM + FiLM; explicit market/task split Unimplemented; must be correct/measurable
R2a Stateful LSTM + task concat Unimplemented recurrence baseline
R2b Stateful LSTM + init-only FiLM Deferred: task unavailable to current initial-state hook
R2c Stateful LSTM + per-step FiLM Active candidate; readout placement first
R2d Init + per-step FiLM on value head only Deferred; matched placements required

R4-v1 Matched explicit solver-state features on FF + recurrent controls Separate observability study

The bec5c77 “R2b per-step” label maps to original R2c. The older init-oriented R4 maps conceptually to R2b; bec5c77 instead used R4 for matched observation features. IDs are not executable flags, and this proposed reconciliation has not been silently promoted to a new canonical schema.

Conditioning placement (open proposal)

Use explicit placement names: R2a input concat, R2c-precell input/gate FiLM, R2c post-cell/readout FiLM, R2b initial-state FiLM, and R2d value-only placement. A post-cell/readout FiLM claim is readout-only only when no other task path (such as concat) reaches the cell; with concat, the transition is already task- conditioned and FiLM is an additional factor. Readout-first is a proposed order, not a settled memory-conditioning decision.

Attribution controls

R1 versus newest-bar R2 changes input history, cold-start/warmup, conditioning, and state lifetime; it is an engineering progression, not an isolated memory proof. Add train-from-scratch same-input/same-conditioning R2c-CARRY versus R2c-RESET before attributing gains to carry state. A zero-state evaluation probe is an OOD diagnostic, not a causal estimate.

Lifecycle contract

Keep input-window, BPTT/unroll (max_seq_len), episode horizon, and reward-statistics window distinct. Define cold start versus causal initial-window warmup. Do not count overlapping bars as new steps. Reset state when the environment actually resets at real termination; a truncated bootstrap difference is not itself a reset, and rollout-chunk detach is not an episode reset. Specify vector-worker ownership, training/inference parity, checkpoint/replay state, and reset semantics before training.

Task and feature controls

The historical legacy_v1 encoder omits reward parameters, bar resolution, regime tags, difficulty, and metadata while exposing a seed feature. New runs use versioned semantic_v2, which represents normalized solver-relevant task fields while excluding episode seed/start location shortcuts; checkpoint compatibility remains explicit. R4-v1 adds position/progress/PnL fields identically to feed-forward and recurrent controls. OHLCV-only recurrence cannot know sampled actions, fills, or position exactly.

Phase B implementation/evidence order

  1. Complete the mandatory Phase A revalidation gate and preserve R0 as a compatibility control, not a validated performance winner.
  2. Produce truthful task/family/regime metadata through the shared episode-evidence contract.
  3. Complete alignment/reward controls on R0; keep reward changes independent of recurrence. Treat the staged reward file as existing/unreviewed here.
  4. Implement and test R1 shape splitting, chronological newest-bar convention, FiLM readout, finite forward/backward, and smoke configuration.
  5. Implement R2a native recurrent LSTM with state lifecycle tests.
  6. Implement R2c readout FiLM and the named R2c-CARRY/R2c-RESET pair.
  7. Only then consider the named pre-cell factor, R2b init-only, R2d value-only, and R3 GRU according to evidence.
  8. Run R4-v1 with identical explicit state features on R0 and the winning recurrent control.
  9. Promote only after held-out chronological evaluation, multi-seed results, state norms, sequence-mask checks, compute/memory, and checkpoint/replay tests.

R1 need not win before R2 is tested. It must be correct and measurable.

Phase B — AZR-inspired curriculum boundary

Status: bootstrap handoff implemented; co-adaptive loop planned.

The local AZR v2 source's Eq. 4 proposer reward is zero at p=0 or p=1, otherwise 1-p; it is not a symmetric 50% peak and not measured learning progress. iTrader should retain deterministic validation, reference/task buffers, and role-specific evidence without claiming reproduction.

Proposer study is separate from R-series solver study:

  1. fixed rule/random validated curriculum;
  2. frozen LLM proposer;
  3. frozen LLM with solver-feedback/reference-conditioned selection;
  4. adaptive proposer only after repeatable utility/uplift evidence.

Use frozen-versus-adaptive reference-buffer updates as a named factor. Adaptation uses validation; reserve an untouched final chronological test. Keep a cost-aware verifier and report generation calls, rejected tasks, tokens/latency, accepted solver timesteps, cost, turnover, and drawdown.

Phase C — operational coupled shell

Status: future operationalization; not the first replay/shadow phase.

Phase B already includes offline/curriculum work and online replay/shadow validation. Phase C means hardening the coupled stack for broader operational use:

  • CurriculumProposer and MarketFramer are operational;
  • online DecisionGate/RiskEngine/Executor shell is hardened;
  • WatsonOW can consume iTRADER as a skill;
  • proposer fine-tuning can use an accumulated, audited corpus later.

Phase C does NOT require immediate replacement of the solver with an LLM.

Phase D — optional Market-JEPA

Status: future/advisory.

Keep representation learning behind the stable market-window and candidate-task contracts. Do not expand to JEPA/MoE as a substitute for causal recurrence controls or truthful metrics.

Promotion rules

No reward, solver, proposer, or online claim is promoted from training curves alone. Use matched data/task identities, chronological validation/test separation, explicit costs, drawdown, turnover, state lifecycle evidence, and a written attribution statement for every comparison.

custom_metrics/episode_return_mean is currently accumulated shaped optimization reward and must not be interpreted as economic return. Historical checkpoints 00002 and 00004 are quarantined as compatibility/negative-test fixtures until the Phase A gate passes. Phase B architecture work may continue independently, but no Phase B capability or uplift claim may use their old PBT scores as a validated performance baseline.
