iTrader / Phase B architecture

From stable solver baseline to governed online intelligence.

A compact masterplan for the PPO/RLVR solver, task-contract layer, proposer split, deterministic risk shell, and future Market-JEPA representation frontier.

System Shape

offline: market data -> curriculum proposer -> TaskSpec -> solver -> capability
online: market window -> MarketFramer -> CandidateTask -> solver score -> gate -> risk -> execution
Phase AStable PPO + FiLM baseline, finite rewards, metrics, manifests, and smoke checks.
Phase BSolver quality, recurrent-window investigation, explicit task contracts, capability profiling.
Phase COffline/online proposer split, shadow MarketFramer, DecisionGate, RiskEngine, Executor.
Phase DOptional Market-JEPA latent market model and candidate-window prior.
Phase A / implemented

Stable Solver Baseline

The implemented path remains PPO + GAE through train_solo_V2.py, with SolverMLPFiLM as the primary task-conditioned model and RewardEngine enforcing finite reward components.

Phase B / active

Solver Frontier

SolverWindowLSTMFiLM is a research frontier, not yet implemented on this branch. The branch should first preserve the MLP baseline, then compare recurrent-window encoding on identical task pools and seeds.

Phase C / planned

Governed Online Loop

MarketFramer emits candidate tasks including WAIT, solver heads score confidence and utility, DecisionGate chooses conservatively, and deterministic risk/execution layers remain final.

Phase D / future

Market-JEPA

Market-JEPA can become a latent market world model or candidate-window prior after solver capability and shadow-mode gating are measurable. It is optional and should stay behind typed seams.
