iTrader / canonical roadmap

Measure the solver first. Couple intelligence only through governed seams.

The route from stable PPO and task-conditioned FiLM to recurrent memory, adversarial curriculum, shadow decisions, and an optional JEPA market representation.

Updated 2026-09-03Branch: feat/codex-adversarialproposerBaseline: SolverMLPFiLM

System Shape

offline: market data -> CurriculumProposer -> TaskSpec -> ITraderEnv -> solver -> capability
online: market window -> MarketFramer -> CandidateTask -> solver score -> DecisionGate -> RiskEngine -> Executor

Phase Rail

Phase A / stable

Solver Baseline

PPO/GAE, family 00, MLP-FiLM, finite decomposed rewards, metrics and manifests.

Phase B / active

Quality + Curriculum

Matched sampling/reward tests, truthful capability slices, recurrent ablation, proposer loop.

Phase C / planned

Shadow Decisions

MarketFramer, WAIT, deterministic gate/risk/execution, complete DecisionRecord.

Phase D / frontier

Market-JEPA

Optional latent representation and framing prior behind stable candidate contracts.

Implemented

  • train_solo_V2 is the independent PPO entrypoint.
  • TaskSpec and ITraderEnv own task and observation contracts.
  • SolverMLPFiLM is the only validated task-conditioned head.
  • pnl_linear is the only proven/default reward; sharpe_only and the pnl_sharpe blend are challengers.
  • OpenAI-compatible proposer backends can use llama.cpp.

Not Yet Implemented

  • Corrected window-LSTM-FiLM and stateful recurrent FiLM.
  • Operational families 01 and 02 or routed family heads.
  • Calibrated family/regime capability records.
  • DecisionGate, deterministic RiskEngine, and Executor flow.
  • Market-JEPA training or inference integration.

Solver Destination

shared market trunk
  -> route by TaskSpec.family_id
  -> policy head[family]
  -> value head[family]

One task routes to one family head. Mixed PPO batches can contain several routes. Build this only after at least two families are real.

Proposer Destination

train_AZR
  -> proposer candidate pool
  -> validation + dedupe
  -> solver rollout/evaluation
  -> r_prop + golden artifacts
  -> next curriculum

train_AZR grows around the coupled loop; it does not replace or dilute train_solo_V2.

Online And JEPA Gate

Phase C starts in replay/shadow mode. LLM framing cannot bypass solver scoring, WAIT, deterministic thresholds, risk, or execution. Market-JEPA may later provide latent context, regime-transition predictions, or uncertainty to MarketFramer, but must preserve the same CandidateTask and downstream decision contracts.

No online influence before capability calibration. PnL remains the sole reward default until a Sharpe challenger wins held-out evaluation. No recurrent default before R1/R2 matched tests and throughput accounting.
