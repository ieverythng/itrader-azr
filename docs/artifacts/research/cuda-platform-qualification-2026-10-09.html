4. Bounded compute-only acceptance protocol

Proposed execution cap: 10 minutes of compute after isolated provisioning, one process, one GPU, one CPU/BLAS thread, sequential cells, no Ray service, PPO optimizer, market data, PBT or checkpoint run. Provisioning has its own GRILL-controlled budget; timeouts stop rather than trigger a second candidate. Only TRAINING's exact lease can authorize execution.

Test all four current structural cells: R0, R0+R4-v1, R1, R1+R4-v1. Use the public selector and actual forward/value interfaces with fixed synthetic, causal-format observations: 60x5 OHLCV, 32 task values and zero/two endogenous state values. R1 is the actual 5-input/156-hidden LSTM plus 256-wide projection; it resets hidden/cell state per decision. No R4-v2 modification.

Correctness first: fixed seed and identical serialized CPU initial weights/ inputs copied to GPU; float32 only; disable task dropout for comparison. Compare logits, values and every parameter/input gradient using a fixed synthetic scalar loss (sum of squared logits plus squared values, averaged). Require finite outputs/gradients and elementwise abs(GPU-CPU) <= 1e-5 + 1e-4*abs(CPU), including zero-reference entries. These are proposed compute acceptance tolerances, not trading thresholds. Compare B=1, B=128 and B=4800 forward; backward at B=128. Do not relax tolerances after seeing failures. Near-tied argmax may differ within tolerance; retain margins rather than declaring economic/action parity.

Set CUBLAS_WORKSPACE_CONFIG=:4096:8 before CUDA initialization, deterministic algorithms enabled, cuDNN benchmark false, cuDNN deterministic true, TF32 disabled for both matmul/cuDNN; AMP, BF16/FP16 and torch.compile disabled. Record effective settings and cuDNN/runtime/architecture identities. CUDA LSTM can have version-dependent nondeterminism; fail if the requested deterministic path is unsupported instead of silently falling back. LSTM caveats, reproducibility. These 2.11 docs supply general caveats; candidate behavior still requires testing.
