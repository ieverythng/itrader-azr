## Findings

1. **NIT — valid source TaskSpec start aliases fail diagnostic preflight.** `1 of the 2 found so far.` `TaskSpec.from_dict` accepts `start_index` as an alias for `start_idx`, and strict `ITraderEnv` reset accepts integer `start_index=1000` exactly. But `load_validation_context` passes raw `source_tasks` to `_assert_panels_do_not_overlap` (`itrader/rl_lib/evaluation/run_checkpoint_replay.py:111-120`), whose `_task_interval` indexes `task['start_idx']` (`:58-60`). Reproduction: persisted validation config with source fixed task `{start_index: 1000, horizon: 96}` plus an eligible diagnostic task `{start_idx: 2000, horizon: 96}`. Expected: normalize the supported alias, validate integer eligibility, and compare intervals. Actual: `KeyError('start_idx')`. Diagnostic panel aliases are normalized by `_load_panel_tasks`, so source and diagnostic inputs are inconsistent. This is fail-closed and does not execute the wrong task; normalize source tasks before interval/eligibility validation or explicitly require/document canonical fields in persisted artifacts. It is a compatibility nit.
2. **NIT — exact adjacency between panel intervals is treated as overlap.** `2 of the 2 found so far.` In `itrader/rl_lib/evaluation/run_checkpoint_replay.py:58-60, 72-77`, `_task_interval` returns `start + horizon` as an endpoint, but the intersection test treats both endpoints as inclusive. Reproduction: `window_size=60`, source `{start_idx: 1000, horizon: 200}`, diagnostic `{start_idx: 1260, horizon: 96}`. Expected: allow the panels because source market rows end at 1199 and diagnostic rows begin at 1200. Actual: raises `Diagnostic evaluation panel overlaps the source selection panel`. The adjacent one-row-overlap control (`diagnostic start_idx=1259`) also rejects, as expected. This is an overly conservative eligibility restriction, not a leakage path, so it is a nit rather than blocking. Representing intervals consistently as half-open or using inclusive `end=start+horizon-1` would make the boundary exact.

## Design principles

1. **Separation of concerns — OK.** `itrader/rl_lib/evaluation/data_partition.py:24-26, 146-178` owns start eligibility; `itrader/envs/itrader_env.py:98-185` resolves Parquet metadata and builds the same partition used by runtime; `itrader/rl_lib/evaluation/run_checkpoint_replay.py:85-128` coordinates replay-panel validation without duplicating range logic.
2. **Programming by intention — violation (NIT; see finding 1).** The exact integer contract is explicit in `itrader/rl_lib/evaluation/provenance.py:77-81`, but replay's source-task path accesses the canonical key directly (`itrader/rl_lib/evaluation/run_checkpoint_replay.py:111-120`) rather than applying the same TaskSpec alias normalization as the diagnostic path (`:49-55`). A supported integer alias therefore fails with an incidental `KeyError`.
3. **Encapsulation — OK.** `data_partition.py:146-190` exposes valid ranges, containment, clamping, and symbol lookup as the partition API; callers use these methods rather than recomputing eligible indexes.
4. **High cohesion — OK.** R4 contract validation and counterfactual state mutation are grouped in `itrader/rl_lib/evaluation/policy_baselines.py:104-145, 267-301`; the CLI performs declared schema/config checks before importing Ray (`run_checkpoint_state_diagnostics.py:41-65`).
5. **Low coupling — OK.** Replay imports `load_market_partition` lazily and reuses the environment's eligibility semantics (`run_checkpoint_replay.py:103-123`); the shared validator is a small dependency in `provenance.py:77-81`. Both nits are local to source-panel normalization and the overlap helper.

The current fixes resolve the prior metadata fallback regression, strict-start coercion/remapping for canonical and diagnostic task fields, EOF/reset identity, R4 tail validation, and ambiguous terminal-index selection within the exercised scope. The two findings are fail-closed compatibility/over-rejection nits; neither path silently evaluates a remapped or overlapping task.
