iTrader Market-JEPA: Phase C world model and candidate-window proposer

Strict implementation blueprint for introducing an I-JEPA-inspired latent market model into iTrader. This is not a WatsonOW component. It belongs to iTrader as a future Phase C solver/world-model head or as the core representation layer feeding MarketFramer.

1. Objective

Market-JEPA should learn a latent world model of the market, enabling MarketFramer to propose semantically meaningful, solver-tractable candidate windows.

market window -> z_context
future/masked market patch -> z_target
predictor(z_context, horizon, task_family) -> z_target_hat

2. Full Market-JEPA pipeline

3. Mathematical basis

zc = fθ(xcontext)
zt = f̄θ(xtarget) where f̄ is EMA/stop-gradient
ẑt = gφ(zc, h, τ, a)
LJEPA = || ẑt − sg(zt) ||²

h is horizon, τ is task family/regime, and a can later represent candidate action framing.

5. Data construction

ItemDefinition
Context windowPast K bars, multi-feature tensor: OHLCV, returns, volatility, cost/spread features, regime metadata.
Target patchFuture or masked segment over horizon H, encoded only as target representation.
Masking strategyTrend continuation, reversal, volatility expansion, chop, and shock windows.
LossLatent target prediction, not raw price reconstruction.

8. Guardrails

  • Do not use Market-JEPA to execute directly.
  • Do not treat latent prediction as proof of future price direction.
  • Use it to improve representation, candidate-window quality, and solver calibration.
  • Keep WAIT / NO_ACTION first-class.
  • Evaluate against the current Phase A/B baseline before promotion.
