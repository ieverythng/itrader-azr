Validation approach

Use narrow red/green cases for ambiguous inputs, followed by integration tests through actual producers and consumers. Do not equate test count with validity. The synthetic 12-step probes are mechanical checks, not trading experiments.

  • Tagged Parquet -> production config builder -> actual PPO -> callbacks -> checkpoint -> restored policy -> frozen replay, for R0 and combined state. Checks actions, logits, values, episode payloads and semantic identities.
  • Same-forward PPO diagnostics compare loss, gradients, RNG, sampled actions and one-update weights with installed original PPOTorchPolicy, including dropout, both optimizer paths, masking and multiple CPU towers.
  • Donor/target PPO tests inspect the first actual optimizer steps, numerical GAE and local/remote/evaluation policy settings; preserve weights, Adam moments, adaptive KL and native counters.
  • Real training_fn restore probes cover manual, Tune self-resume and PBT receipt routing. Only Tune's context/report boundary is substituted.
  • Persisted four-arm/three-seed analyzer tests exercise final promotion, not only helper predicates. Adversarial receipts, different data/source/runtime, earlier checkpoints and mismatched CSV metrics must not promote.
  • Two fresh subprocess receipt probes bind output identity to observed processes; the independent reviewer additionally executes actual checkpoint replay CLIs. Sources must remain frozen during a pair to match contracts.
