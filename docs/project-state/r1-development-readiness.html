1. Capture clip fraction at its producer

Source inspection of installed Ray 2.58 PPOTorchPolicy.loss and stats_fn confirms that the legacy policy computes the PPO likelihood ratio but exports no clipping fraction. train_solo_V2._extract_report already looks for clip_fraction / clip_frac, so changing the plot or adding another alias cannot recover it. The legacy API stack remains explicitly selected.

For the actions actually sampled in the rollout, define:

r = exp(current_action_logp - rollout_action_logp)
outside = (r < 1 - clip_param) OR (r > 1 + clip_param)
clip_fraction = sum(outside AND valid) / sum(valid)

This measures ratios outside the clipping interval. It differs from the advantage-sign-dependent fraction where clipping determines the chosen surrogate term. If the latter is added, name it separately.

Implementation contract:

  • Own the instrumentation in a small version-pinned legacy PPO policy adapter, not in ITraderEnv, the reward engine, evaluation callbacks or the dashboard.
  • Capture detached counts from the same forward/distribution used for loss. Do not call super().loss() and then perform a second model forward to infer the ratio: the current model uses task dropout during learning, so that can measure another policy realization and consume RNG.
  • Reuse the loss validity mask. R1 has no cross-step rollout state and does not introduce padded RLlib sequences; later R2 must exclude sequence padding.
  • Reduce clipped and valid counts across towers/minibatches/SGD passes before division. Label the interval as all optimizer sample-visits in one train report, not unique environment transitions or a post-update evaluation. Repeated SGD passes intentionally count repeated visits. Do not average unequal minibatch fractions without weighting. Exclude initialization/dummy loss calls and reset the report accumulator after consumption.
  • Preserve missing versus zero: old reports remain unavailable, empty valid sets are unavailable, non-finite ratios are diagnostic failures. Keep metric definition/version, valid count and reduction scope in the evidence contract.
  • Wire the chosen policy class through training and restore registration, then through learner stats -> report rows -> summaries -> browser. Do not switch to RLModule/EnvRunner as part of this instrumentation.

Required probes: ratios below/at/inside/at/above the interval; positive and negative advantages; masked padding; unequal minibatches; repeated epochs; zero-valid rows; non-finite values; real legacy learner propagation. Compare instrumented versus original policy with identical weights, batch and RNG: loss, gradients, sampled actions/RNG state and one-update weights must agree. Include task dropout in that parity test.

Reference: the PPO implementers' implementation-details account describes clip fraction and the importance of implementation-level controls; the installed pinned Ray source is the authority for the adapter.

2. Stamp and validate replay provenance

run_checkpoint_replay.py and run_checkpoint_state_diagnostics.py now share invocation/completion receipt construction in evaluation/replay_evidence.py. evaluation/provenance.py owns checkpoint, dataset and source hashing. Historical reports without producer identities remain unknown; they are not rewritten.

Receipt acceptance contract (implementation coverage is tracked in the audit):

  • fresh invocation UUID and process-instance identity established at process entry, with PID, process creation time, host identifier and UTC start/end;
  • operation (episode replay or state diagnostic), checkpoint tree SHA-256, selected progress/generation, dataset hash, source/evaluation panel hashes, resolved effective config hash and dirty source-tree hash;
  • runtime versions, device/determinism settings, observation schema and seeds;
  • artifact filenames, byte hashes, row counts, completion status and metric contract version.

An invocation UUID alone cannot distinguish two calls inside the same process. The harness should launch fresh subprocesses, record their process identities and exit results, and bind each invocation receipt to the launch record. An episode replay and a state diagnostic are separate invocations even if grouped under a single human-readable replication directory. These records support auditable provenance; they are not cryptographic proof against fabrication.

Verify the indexed checkpoint digest against the actual tree before restore; verify dataset and effective panel/config identities before evaluation. Commit the completion receipt atomically only after artifact hashes are known. A failed/interrupted run must not look complete, and output paths must not silently overwrite another invocation. Compare deterministic payload hashes, not the whole receipts, because execution IDs and times should differ.

Source-panel parity must compare episode identities, action/reward traces and the underlying metric vector. Matching the scalar selection score alone is insufficient: the current non-flat selection score maps distinct near-flat policies to zero. Use separate names for score parity, payload parity and verified process replication. Where historical reference traces are absent, report the stronger checks as unavailable rather than inferring exact parity.

The comparison gate must require distinct verified process instances, identical effective evaluation contracts/checkpoint identity and matching payloads. Copying a directory, changing a panel, reusing an invocation ID or modifying the checkpoint must fail. Legacy receipts remain readable as unknown-process provenance; do not backfill invented IDs into G0 evidence.
